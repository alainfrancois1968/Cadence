Upsampling notes
The first call to /stream_from_track_upsampled for a given album + start track + target rate is slow because it decodes, resamples (FFT), and re-encodes the entire remaining album before returning any audio. The result is written to cache/upsampled/. Subsequent requests for the same combination serve the cached file immediately. Default target rate is 96 kHz. Lower rates (48000) are faster for testing.

Database Tables

  • tracks – path, title, artist, artist_id, album, album_id, track_id, track_number, duration, format, stream_url, genre, dr_score
  • genres – unique genre names
  • track_genres – many-to-many link between tracks and genres
  • artists – artist_id, name
  • album_queue – album_id, artist, artist_id, title (download queue, not playback)

Download layout

Album downloads create this structure under library/:

library/Qobuz/{artist_id} - {artist name}/{year}/{album_id} - {album title}/
    cover.jpg
    01. {track_id} - {title}.flac
    02. {track_id} - {title}.flac
    ...

Existing files are skipped. Tags and front-cover art are embedded with lofty. A dynamic-range score is computed and stored in the tracks table.

Cache layout

Upsampled streams are cached here:

cache/upsampled/{album_id}_{track_id}_{target_rate}.flac

These files can be deleted safely; they will be regenerated on the next request.
